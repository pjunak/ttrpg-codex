# Internationalization (i18n) — deep reference (ttrpg-codex)

> Canonical contract for localization. Read this before changing
> user-facing text, catalogs, locale selection, or addon i18n.

## Internationalization (i18n)

UI strings are authored as **English source keys**; translations are
served per user through **Settings → Language**. Code/admin stays
English. English is the default UI language and Czech is the only
shipped translation.

**Per-user, NOT campaign-wide.** Language is a personal browser choice
(`localStorage['codex_lang']`), never synced to the server like the
theme is. The DM and each player pick independently — the deliberate
divergence from the otherwise-mirrored theme system.

**Resolution:** explicit stored choice → English default. Browser or
operating-system locale does not silently change the interface. The
chosen catalog is loaded once at boot **before the first render**
(`await I18n.load()` in app.js
`DOMContentLoaded`, before the first `Sidebar.render()`), so there's no
flash of the wrong language.

### `web/js/i18n.js` (`I18n`)
Self-contained IIFE — imports NOTHING app-side, touches no DOM at load
(so Node tests import it cleanly). `t()` returns PLAIN text — **callers
`esc()` before innerHTML**, exactly as for plain literals. Public API:
- `load()` — resolve locale, set `<html lang>`, fetch en + active catalog
  (idempotent; never refetched on SSE/re-render — only `setLocale` to a
  new language fetches).
- `t(key, params?)` — fallback chain active → en → key; `{placeholder}`
  interpolation; never throws (missing key → the key, or `⟦key⟧` when
  `localStorage['codex_i18n_debug']==='1'`).
- `plural(key, n, params?)` — native `Intl.PluralRules` picks the bucket
  from a `{one,few,many,other}` catalog entry. Czech integers →
  one(1)/few(2-4)/other(0,5+); `n` is supplied to interpolation.
- `formatDate(value, opts)` / `formatNumber(n, opts)` — `Intl.*` using the
  active locale.
- `relativeTime(ms, now?)` — `Intl.RelativeTimeFormat`; backs the
  `utils.humanTime` shim (now a thin delegate — its many callers are
  unchanged).
- `setLocale(id)` — persist + switch + re-render (async: fetches a not-
  yet-loaded catalog once). Wired to the Settings dropdown.
- `detectLocale(languages?, stored?)` — pure (DOM-free, testable).
- `getLocale()` / `availableLocales()` (`[{id, endonym}]`) /
  `applyLocale()` (sets `<html lang>`) / `hydrate(root)` /
  `register(id, catalog)` (tests + pre-load) / `setRerender(fn)` (app.js
  injects the re-render closure — same late-binding pattern as
  `setWikiLinkResolver`).

### Catalogs — `web/i18n/en.json` (source) + `cs.json`
Flat, dotted keys (`nav.characters`, `cloudmap.events`, …); plural
entries are the only nested values (CLDR-bucket objects). Served by
`express.static(WEB_DIR)` at `/i18n/*.json`, shipped via `COPY web` (no
server/Dockerfile change). Adding a language = one `/i18n/<id>.json` +
one row in `I18n` `LOCALES`.

### Wiring (settings.js + app.js)
- `I18n` is in the `ACTIONS` map; the dropdown `<select>` dispatches
  `I18n.setLocale($value)` through the delegated `data-on-change`
  contract.
- `_languageHtml()` renders `#settings-language-select` from the fixed
  `availableLocales()` registry. The Language tab is visible to DM and
  player roles and changes only this browser.
- Switch re-render = `_fullChromeRerender()` (the SSE `_applyRemoteChange`
  fan-out **minus** `Store.load`). **Mid-edit guard:** if
  `EditMode.isDirty()`, only the editor-free chrome flips + a toast; the
  full `navigate()` re-render defers to the `editmode:clean` drain
  (`_pendingLangRerender`) so a live EasyMDE/CodeMirror editor isn't
  destroyed with its unsaved text.
- Static `index.html` chrome (loading text, bottom-nav, map sheet,
  search/settings labels) is English by default + carries `data-i18n` /
  `data-i18n-title`; `I18n.hydrate(document)` swaps it at boot + on
  switch.
- Sidebar page labels come from `SIDEBAR_PAGES[].key` via `I18n.t`
  (`Sidebar._label`).

### Scope boundary (chrome vs content)
Only UI **chrome** is translated. User-authored content (names,
descriptions, markdown bodies) AND **DM-editable enum/section labels**
(attitudes, pin types, statuses, relationship types, and sidebar
SECTION labels in `SIDEBAR_LAYOUT_DEFAULT`) are CONTENT — left as
stored. `SIDEBAR_PAGES` link labels (a pure hardcoded registry, never
persisted) ARE translated.

### Catalog coverage

Product-facing chrome is catalog-backed across navigation, dashboard, editors,
wiki pages, maps, timeline, mind maps, Settings, search, widgets, addon
management, and status/error banners. Keys are namespaced per area
(`nav.*`, `action.*` shared verbs, `settings.*`, `editform.*`,
`editmode.*`, `wiki.*`, `map.*`, `cloudmap.*`, `timeline.*`, `dm.*`,
`search.*`, `sidebar.*`, `widget.*`, `addons.*`, `app.*`, `store.*`,
`time.*`, `loading.*`, `mapSheet.*`, `lang.*`).

**Two test guards** (run in `npm test`): `test/i18n.test.mjs` (engine +
catalog parity — cs covers every en key) and **`test/i18n-keys.test.mjs`**
(scans the sources and asserts every LITERAL `I18n.t('…')`/`I18n.plural('…')`
key + every `data-i18n` attribute actually exists in `en.json`). When you
add a new UI string: wrap it in `I18n.t`/`plural` and add the key to BOTH
`web/i18n/en.json` and `cs.json` (the parity + key tests enforce both).

Core owns only the `import.*` copy used by its campaign-data import adapter,
plus the Addon Manager description for the reviewed `data:import-provider`
permission (`addons.permImportProvider`). DM Tools owns the visible Import
Center route, adapter-selection chrome, and planning-adapter English/Czech
catalogs through `host.i18n`; they do not enter core catalogs. There is no core
`nav.import` entry.
Provider diagnostics remain structured plain text. The UI maps its known
stable diagnostic codes to localized copy, escapes fallback messages and
locations, and never accepts provider HTML.

**Deliberately NOT translated (content or internal contracts):** DM-editable
enum/content defaults in `data.js` and section labels in
`SIDEBAR_LAYOUT_DEFAULT` are seeded in English so a fresh first deploy starts
in English; existing instances keep their persisted labels. Theme display
labels are UI chrome and are catalog-backed. Enum *id* values used as keys
(e.g. the `'střední'` priority id)
remain unchanged because they are persisted on records and hardcoded in
`wiki.js`/`cloudmap.js`; only their labels are English. Also excluded are the
`localeCompare('cs')` sort sites and **addon-framework
internal diagnostics** (`addon-deps.js` blocked-reason strings,
`addon-fragments.js` conflict message, the thrown `Error(...)` API-violation
messages in `addons.js` — developer-facing, surface only for a misbehaving
installed addon).

### Declarative addon catalogs

API-v2 addons may require `i18n.catalogs` and declare a package-relative
locale map:

```json
"capabilities": { "required": ["i18n.catalogs"] },
"locales": { "en": "locales/en.json", "cs": "locales/cs.json" }
```

English is the mandatory, complete source catalog. Other catalogs may be
partial but every supplied key must match the English value shape and
placeholder set. Install/dev-install reject unsafe paths, non-JSON or
non-regular files, invalid/duplicate locale ids, malformed JSON, unsafe keys,
unsupported value shapes, placeholder drift, and bounded key/file/count/length
limit violations before activation.

Catalogs are scoped by addon id; they never merge into core `I18n` or another
addon. The facade passed to `register(host)` exposes
`host.i18n.{locale,t,plural,formatDate,formatNumber,relativeTime}`. Translation
resolution is exact locale → base locale → English → key, interpolation and
plural selection share the core formatter behavior, and `t()` still returns
plain text that must pass through `host.h.esc()` before HTML injection.
Missing keys diagnose safely without breaking rendering.

`web/js/addon-i18n.js` is the shared live/harness engine. The English catalog
loads and validates before the addon module is imported; a broken English
catalog blocks only that addon. An unavailable optional translation warns and
falls back. Runtime catalog cache entries include addon id, active package
revision, locale, and path. Replacement/content revision changes dispose the
old scoped facade, abort pending loads, clear its cache entries, and reject
late stale responses, so reconciliation cannot restore old catalogs or
duplicate registrations. The published harness validates addon catalogs via
`validateAddonCatalogs` and accepts `opts.catalogs` plus `opts.locale` for
locale-switch/fallback tests.

⚠ **When migrating a placeholder/
title, check nothing queries the DOM by that text** — a `querySelector(
'input[placeholder="…"]')` breaks once the placeholder is localized (this
bit the rank-chain name input: it now carries a stable `.rank-chain-name`
class that `editmode.saveFaction` queries instead).
